### Screen mirror model

The remote window is the browser running on the owner's VPS, not his laptop Chrome. Profile labels (Personal, Brand A, Brand B, etc.) map to independent persistent profile IDs on fresh installations. Only one login window should be active at a time. Verify each signed-in identity, eligibility, project and live models before moving to the next. Close the mirror after onboarding; the profile remains. Private mirror sessions expire and can be reissued without deleting or logging out a profile. Never expose VNC/CDP ports to the internet. Existing imported installations may share a desktop; do not describe them as isolated desktops.

### Provider permissions

Flow login needs no distributed Google API key. It does not grant posting access. [Platform permissions](PLATFORM-PERMISSIONS.md) and [connection experience](CONNECTION-EXPERIENCE.md) list exact registration/redirect/eligibility steps. Current Google scopes are `youtube.upload` + `youtube.readonly`; optional archive `drive.file`. Instagram Login uses `instagram_business_basic` + `instagram_business_content_publish` on an eligible professional account. Facebook Page publishing uses `pages_show_list`, `pages_read_engagement`, `pages_manage_posts`, with configuration/review as required. Request only enabled capabilities. An agent can configure what its tools allow; it cannot grant provider approval or consent itself.

A shared verified OAuth registration could reduce setup, but requires a maintained public auth service, provider approval and a separate trust/operating model. It is not included in the independent repository. Do not tell a new user “only Allow” until that registration path exists.

### Setup receipt and recovery

Return dashboard URL, own MCP URL, installation/source revision, resource IDs/region, readiness table, owner-only remaining steps, costs and restore/offboarding instructions. Keep pairing URLs, keys and browser data out of GitHub, cloud logs and public outputs. Current owner sessions last eight hours; a new private pairing link is needed after expiry. Persistent passkey/owner sign-in is a planned UX improvement, not implemented.

On AWS timeouts inspect the original stack/resources. On rendering/upload timeouts poll/reconcile original jobs. On Google login challenges hand control to the owner. On missing custom-plugin/event/native-byte capability mark the appropriate mode blocked/pending, without changing to a paid API or another person's VPS. Schedule must be later than VPS startup, or explicitly authorize an always-on host.
