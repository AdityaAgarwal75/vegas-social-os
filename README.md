# Vegas Social OS — agent first

**Give this repository link to your ChatGPT. Your agent owns cloud setup. You onboard through a dashboard and approve creative work in chat. No local PC or user-managed VPS.**

Repository: **https://github.com/AdityaAgarwal75/vegas-social-os**

For a setup request, share that link and ask your agent to configure Vegas Social OS. The agent must read **[BOOTSTRAP.md](BOOTSTRAP.md)** and **[agent-manifest.json](agent-manifest.json)** before acting. You are not expected to clone repositories, install packages, run terminal commands, configure databases or paste code.

**0.2.0 alpha:** agent bootstrap, onboarding, encrypted Supabase state and private remote-browser login are implemented in source. Full cloud deployment, real ChatGPT installation, real Google/Meta login and Flow generation still require an end-to-end trial. The repository cannot create permissions or hosting access that your agent does not have.

## What you do

1. Give the repository link to a supported ChatGPT/Codex agent.
2. Authorize any missing GitHub, Supabase, runtime-hosting or plugin tools it requests. Approve paid provisioning separately.
3. Open the private onboarding URL the agent returns.
4. Enter your name, brand, timezone, goals and channel details.
5. Connect YouTube, Instagram and as many authorized Flow accounts as your runtime can support. Sign in directly with the provider; complete consent/2FA yourself.
6. Accept plugin installation if your ChatGPT host requires that final consent click.
7. Work in ChatGPT: review concepts, approve native images, review videos and approve exact releases.

There is no dashboard image generator. Native ChatGPT images are the only image source. The agent must verify both image-tool availability and transfer of real generated bytes to the runtime. If that host cannot transfer them automatically, the zero-manual image stage is blocked; the agent must say so rather than inventing a workaround.

## What the agent does

| Setup task | Agent responsibility |
|---|---|
| Source | Read/pin the repository; use an isolated checkout; create a private mirror only when supported and useful |
| Data | Provision/select a dedicated authorized Supabase project; apply/verify service-only state schema |
| Cloud runtime | Provision a managed app service, private cloud volume, HTTPS route and graphical browser dependencies; no local PC/user-managed VPS |
| Credentials | Configure provider developer apps where tools permit; inject secrets directly into the runtime secret store |
| Onboarding | Create an expiring private link and verify dashboard readiness |
| Flow sign-in | Open an account-specific isolated browser in the dashboard; keep its session on the user's runtime |
| Plugin | Package/create one remote master plugin; show supported install/consent UI and verify a harmless call |
| Validation | Save an evidence-based receipt; never label failed checks complete |

Provider developer-app review, account consent and platform installation consent cannot be bypassed. If app-registration tools are unavailable, the agent reports that exact connection gap. It must not hand setup code to the user.

## Why GitHub + Supabase still need a runtime

| Component | Role |
|---|---|
| GitHub | Public source, versioning and tests |
| Supabase | Authoritative encrypted installation state through a server-only transactional revision RPC |
| Managed cloud app service, initially Render | MCP backend, private dashboard, isolated Chrome profiles and FFmpeg |
| Google Drive, when authorized | Private media archive; does not replace browser execution |
| ChatGPT | Strategy, scripts, native image generation, creative iteration and approvals |
| Official social APIs | YouTube uploads and Instagram Reels |

GitHub-hosted jobs use disposable environments. Supabase Edge Functions are bounded lightweight runtimes. Neither replaces persistent Chrome sessions. The agent provisions a managed cloud app service through a connected deployment tool; no local computer or user-managed VPS is involved. Render is the initial blueprint candidate and needs a live browser/sandbox trial. No maintainer VPS/accounts are used. Read [cloud architecture](docs/CLOUD-ARCHITECTURE.md).

Existing ChatGPT Drive access must be checked for uploads. It does not automatically grant this backend a token. The agent can use an authorized host connector or the included private Drive OAuth/archive adapter.

## After setup

The master plugin manages explicit channel destinations, two original concepts, scene prompts, ChatGPT-native keyframes, capped Flow jobs, review and platform-specific publishing. Generation and publishing have separate IDs; unknown writes are never automatically retried. Account connection does not authorize posting.

Daily briefs can be consumed by a supported host scheduler. The plugin itself cannot wake ChatGPT's native image tool. No fixed number of Google accounts or guaranteed daily credit amount is assumed; actual eligibility, balances, resource capacity and current provider rules apply.

## Current boundaries

This remains an independently installed **single-operator** system, not a centrally hosted multi-tenant service. Hosting connections differ across ChatGPT environments. The supplied agent planner is capability-based, not a universal cloud-provider connector. The Docker/browser recipe is source-only until live container verification. Flow UI automation is experimental. Full comments/DMs, carousels, additional social platforms and advanced Flow edits remain future work.
