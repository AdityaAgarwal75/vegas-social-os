# Channel-specific creative memory and evidence

1. Discover actual tools and account/channel relationships. `content_context(channel_id)` retrieves only that channel's memory and evidence; it never makes a provider request. Read the saved strategy, last 15 titles, pinned craft and limitations.
2. Research real audience problems and current facts. Use public metadata search to discover primary sources, then read and cross-check them. Distinguish publication date from retrieval date. Save sources; label unsourced original angles creative hypotheses, never trends. Choose a pillar, concrete payoff and two different hooks.
3. Draft script, on-screen text, caption, separate shot prompts and references. Use one action and clear camera travel/speed/end per clip. Explicitly lock subject appearance from the supplied image. Add audio/dialogue only where supported. Put precision text, overlays and complex sequencing into the edit.
4. Review a weekly calendar via `content_plan_save`; calendar approval does not approve a public upload. Use `studio_quality`/`reel_review` for timing and writing estimates, not predicted retention. Choose one measurable experiment.
5. Save actual decisions through `content_memory_save(channel_id, project_id, fields, request_id)` before release. `fields` requires hook and video_prompts; include visual_hook, hook_family, format, script, image_prompts, template_ids, audio_plan, edit_plan, hypothesis, primary_metric, duration_seconds, aspect_ratio, content_pillar and actual reference_asset_ids when known. Never invent missing historical prompts. Revisions are new immutable IDs.
6. Produce with the existing approval, credit and output-correlation guards. `publish_prepare` snapshots the available creative decisions and final asset manifest. Public release still requires exact owner approval and normal publishing tools.
7. If requested, enable `learning_policy(enabled=true)`. A separate daemon observes confirmed public posts at about 6/24/72/168 hours, at most one provider observation per five-minute tick, with one-hour retry cooldown. It skips missed windows instead of inventing historical counts. Restart-safe records prevent duplicate checkpoints. Private/unlisted tests are excluded.
8. YouTube's existing authorized videos.list provides public counts and actual publish time, not audience retention. Instagram metadata counts are distinct from Insights; additional metrics are attempted only if actual stored scopes include Insights permission. Missing permissions remain unavailable. Never acquire scopes or change OAuth consent silently. Owner-supplied data through performance_observe is labeled unverified and excluded from automatic baselines.
9. Compare at the same age, account, format, aspect and duration bucket. Automatic comparisons need five other distinct comparable public releases; otherwise report insufficient evidence. Metrics are descriptive, not causal. Views alone cannot diagnose weak hooks, and Shorts views are not engaged views.
10. Read pending reviews in content_context during the next real ChatGPT session. Save a restrained hypothesis and one changed variable with `learning_lesson_save`, citing real observation IDs. Keep channel-specific lessons, counterexamples and limits. No code rewrites its own system instructions, no weights are trained, no idle ChatGPT session is represented as an active strategist.

## Concrete three-shot path

Prefer plan_save → concept_select → image_tasks → image_attach → images_approve → video_request/video_poll → video_edit/edit_status → publish_prepare. For a studio-originated brief: studio_brief → studio_draft(two variants) → studio_select(owner choice), then copy both saved variants' title/hook/script and every image_prompt/video_prompt into plan_save using the same channel/project. concept_select on that actual plan records the same selected index and separately approved credit ceiling. A studio selection creates no production plan or spend authority by itself.

For a three-shot unboxing, preserve scenes[0], scenes[1], scenes[2]. Attach the actual separate keyframe assets to those exact indices. Keep their three exact video prompts. Submit one video_request for scene 0, poll it to a known outcome, then scenes 1 and 2 under their own stable IDs/caps. The three scenes are not a three-ingredient render.

Observation enablement covers all eligible public confirmed releases in the installation across channels; there is no per-channel policy switch in 0.13. Existing account/channel evidence remains isolated. The daemon can collect counts tomorrow without ChatGPT, but a strategic review tomorrow requires an actual verified host trigger; otherwise it waits for the next user/host session.
